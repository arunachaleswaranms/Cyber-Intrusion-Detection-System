# ADR 0002: Build v2.1 as an evidence-first local analyst workbench

Status: **Accepted for implementation**

Date: 2026-09-12

## Context

v2.0 produced a reproducible but limited offline UNSW-NB15 benchmark. The frozen
binary model has useful attack recall but a 26.89% false-positive rate, while the
multiclass model has weak minority-family generalization. The prepared schema has
42 flow features but no timestamps, IP addresses, or host identity.

The next release should improve portfolio and learning value without presenting
the benchmark as a production IDS, weakening the one-time official-test boundary,
or exposing users to arbitrary pickle deserialization.

## Decision

Build v2.1 as a local Streamlit analyst workbench with two modes:

1. A default evidence mode driven only by committed v2.0 JSON and hashes.
2. An opt-in inference mode driven only by an app-controlled trusted local model
   pack created or registered through an explicit command-line action.

The browser will accept bounded feature CSVs but never model uploads, model URLs,
or arbitrary model paths. Model outputs will be labeled uncalibrated scores.
Queue bands will be presented as review ordering, not threat severity or business
risk. The interface will use record sequence unless optional real timestamps are
provided and will not display absent IP or host data. Manifest, path, hash, trust,
and runtime checks occur before deserialization; object and internal-metadata
validation occurs immediately afterward.

SHAP remains behind a technical compatibility and correctness gate. If the gate
fails, a follow-up ADR must approve a bounded alternative or reduce explanation
scope; the UI will not mislabel another technique as SHAP.

The full contract is in [`../v2.1-design.md`](../v2.1-design.md).

## Consequences

### Positive

- A clean clone has a useful, reproducible reviewer experience.
- Frozen benchmark evidence stays separate from new user-supplied analyses.
- The riskiest model-loading action cannot be initiated from the web UI.
- Known schema limitations remain visible rather than being filled with invented
  SOC-style fields.
- Core behavior can be tested independently of Streamlit.

### Costs and limitations

- Inference requires an explicit local setup step and trusted artifacts.
- The first release remains offline and batch-oriented.
- Scores cannot honestly be called confidence until a separate calibration study.
- Per-record explainability is conditional on the technical gate.
- Checksums do not make an artifact trustworthy; local provenance and user intent
  remain part of the trust boundary.

## Rejected alternatives

| Alternative | Reason rejected |
|---|---|
| Dashboard that requires the dataset and model at startup | Prevents a clean-clone portfolio review and couples presentation to private local artifacts. |
| Upload `.joblib` models in Streamlit | Loading an untrusted pickle-compatible artifact can execute arbitrary code. |
| Publish final model files in Git | Expands binary artifact and supply-chain risk and conflicts with the project's no-generated-model rule. |
| Call every record plot an alert timeline | The base prepared schema contains no event time. |
| Display probability as confidence or severity | v2.0 did not establish calibration or operational impact. |
| Use the official test for threshold tuning or SHAP background | Violates the frozen final-evaluation boundary and encourages test-driven iteration. |
| Add PCAP/live capture in v2.1 | Feature-parity and parser trust questions require the separate v3.0 design review. |
